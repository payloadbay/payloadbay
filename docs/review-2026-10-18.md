editor and rejects branding writes even for instance owners. No environment flag
pretends to verify a license. A later implementation must add verified enterprise
entitlements and apply branding consistently across application and email surfaces.
Forkable notification modules remain separate from product white-labeling.

### Additional audit finding for maintainer review

Monaco's helper-name precedence map in `components/code-editor.tsx` still lists
instance/workspace/project and omits the organization level. Server-side helper
resolution and authorization remain authoritative, but overlapping helper names
can therefore show the wrong editor declaration. This additional finding is
reported separately rather than silently expanding the approved visual review.


The token creation OpenAPI schema still accepts an instance scope before the
handler rejects it. The UI offers only personal/customer contexts and instance
key creation is denied, but the public schema should eventually express the same
restriction instead of advertising a rejected input. This documentation/contract
finding is separate from the implemented creation-context controls.
