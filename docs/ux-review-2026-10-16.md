## Confirmed defects corrected in this pass

- Status choices previously mixed incoming processing states and outgoing delivery
  outcomes. The API rejected legitimate-looking UI choices. Each view now offers
  its valid states; multiple statuses are ORed, and no matches are an empty result.
- Attempt rows had status summaries but no captured-response inspection. Add a
  scoped attempt detail route exposing captured body bytes only with payload-read
  permission; metadata visibility alone must not reveal them. Current storage
  captures up to 64 KiB of body, not response headers; do not fabricate headers.
- Use visible semantic status chips on narrow and wide tables.
- Empty secret keys instead of prefilled real-looking values. Distinguish the
  secret's key/value from the script key used as `ctx.secrets.MY_KEY`.
- Format loaded saved drafts as well as saves and copied templates. Preserve an
  incomplete invalid draft when Prettier cannot parse it, so the user can fix it.
  Seed/template source must contain actual tabs and readable block structure.
- Restore page-owned scrolling instead of trapping the page in a contained inner
  scroll pane. Keep the coordinated sticky header/preview notice.

   Shared code, with instance administration at the bottom. Scope replacement

2. Opening the drawer in a workspace, project or route shows that scope's controls

   working page. Selecting an actual destination performs navigation.
3. Make search a separate HeroUI Pro Command dialog with a clear/reset control,

4. Breadcrumbs use the actual resource name and a separate final section matching
   the menu label: project → route name → Scripts. No `Ingress route · code` suffix.
   Shorten or collapse ancestors on narrow screens while preserving access to them.
5. Reproduce keyboard open/close and browser-toolbar resize with drawers and forms.
   A screenshot alone cannot establish the viewport bug's cause. Verify viewport
   bounds, reachable footer actions, scroll restoration and absence of stale inline
   heights after closing the keyboard; distinguish emulation from real Android.

## Authorized native script/dependency model

- Use real TypeScript module imports, for example
  `import { describe } from "@shared/DemoHelpers";` when the module exports
  `describe`, or a default import when the module exports a default value.
  Namespace imports remain valid TypeScript, but should not be forced by forms.
- Resolve available modules with Monaco completions/type information. Typing an
  import should be sufficient; the script editor becomes the primary workflow.
  A derived dependency inspector can show pinned revisions and explicit updates.
- Resolve/pin an immutable revision when adding a dependency to a saved draft;
  publication pins it for every queued execution. Avoid invented npm-style semver
  until a real version contract exists. No silent updates to queued work.
- This requires changing the current processing/middleware editor's protected
  wrapper/import projection, compiler checks and publication dependency resolver
  together. Do not replace `import *` text cosmetically while leaving fake or
  uneditable dependencies underneath it. Keep import/export separation and Prettier.
- A middleware's descriptive function name can follow its configured name while
  the platform invokes a fixed default export. Review that lifecycle contract
  before changing compiler checks; do not rename only the visible editor wrapper.
- Present middleware as a table. Reorder editable local rows within their stage,
  with drag and keyboard controls backed by an atomic version-checked mutation.
  Inherited required policy remains distinguishable and protected.

## Playground and dry-test presentation — proposed

Cloudflare Trace builds a simulated request from URL, method, headers/body and
other properties, then presents evaluated configurations in execution order.
For Payload Bay, use the same input → execution → outcome progression, with
explicit simulated effects rather than only an opaque result dump.
[Cloudflare Trace](https://developers.cloudflare.com/rules/trace-request/how-to/).

Hoppscotch separates request parameters/body/headers and response status/headers/body.
That supports a compact client workspace rather than a series of settings cards.
[Hoppscotch features](https://hoppscotch.com/features).


Use a connected request/response workspace: method + URL + Send; request headers
and body; response status/time and body/header tabs. Keep request data editable
and response data read-only. Use the same arrangement for synthetic script tests,
with stage, supplied request and simulated capabilities explicit. Avoid treating
an API-client task as unrelated configuration cards or dumping an opaque result.

## Reusable principles from this review

The maintainer reaffirmed the context and native-source direction. General principles
belong in UI/UX guidance; the feature details above remain acceptance criteria.

- Changing context should replace irrelevant controls, not stack every scope.
- Navigation tools must explain their destination and allow users to clear intent.
- Developer-facing editors should preserve familiar language semantics and show
  the executable source; hidden orchestration must not masquerade as editable code.
- Filters must use the vocabulary and data model of the collection being shown;
  empty results, invalid inputs and service failures are distinct states.
- Inspection should expose actionable evidence behind a status, subject to access.
- Mobile acceptance includes keyboard/toolbar transitions, native scroll gestures
  and restored overlays, rather than only screenshots at a narrow width.
