# Implementation review against installed source

This supersedes the earlier inference that rendering all catalog entries establishes
replacement readiness. It does not. This is an independent implementation study;
Pro stays in the product and remains the licensed reference.

Baseline inspected: `@heroui-pro/react` **1.0.0-beta.10**, installed under
`apps/web/node_modules/@heroui-pro/react/dist/`. The installer version is not the
installed component version. Source paths below are relative to that `dist/`.
The library's JavaScript, variant definitions and component CSS were inspected,
including supporting modules for trees, sheets, calendar, editor and feedback.
Public React Aria and engine implementations were followed where behavior is
actually delegated. Vendor files are neither vendored nor imported by local UI.

## Review method

For each composition, distinguish the component's defaults from caller-supplied
content. Trace root/context ownership, emitted DOM and slots, state transitions,
keyboard/pointer events, portal positioning, CSS states, motion and preferences.
Use equivalent data, dimensions and content on both sides. Browser checks need
an actual interaction: pointer movement for hover, held presses for confirmation,
intermediate frames for animation, and keyboard focus for composite controls.
A final screenshot or the presence of a CSS duration is insufficient.

The continuous catalog is the default review page. Both columns contain the same
52 sections. Scrolling is synchronized by section and relative offset rather than
whole-document percentage, because implementation heights can differ. Standalone
component URLs remain available for focused interaction tests. Fixed-position
examples have a local containing block so one example cannot cover unrelated rows.

## What is and is not established

The fixes above address actual code and composition defects. They are not approval
of all 52 entries, nor certification of every Pro variant. The remaining feature/API
differences are explicit in the matrix. Do not remove Pro or describe these as
complete drop-in replacements based on a green render sweep.

Motion is component-specific. Source absence of an explicit reduced-motion rule
does not prove intended animation policy. Recharts/Embla/NumberFlow and public
React Aria may own behavior beneath a Pro wrapper. The local descriptor APIs and file-tree animation implementation are independent alternatives, not renamed Pro internals. Keep their differences visible during review.
