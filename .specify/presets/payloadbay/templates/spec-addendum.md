
## Behavior and delivery scope

- State the smallest complete user flow this feature will deliver and its
  observable acceptance criteria.
- Include relevant rejection, failure, retry and recovery outcomes. Make
  reliability promises explicit when applicable, including who handles duplicates.
- Distinguish implemented behavior, reported experiments and proposed behavior.
- Record non-goals so the feature does not expand into unrelated infrastructure.
- Express user-visible rules as concrete Given/When/Then examples where useful.
  Executable acceptance evidence is required; a separate Gherkin tool is required
  only when the project already uses it or the plan justifies introducing it.
