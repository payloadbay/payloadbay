# Payload Bay task guidance

Test-first tasks are mandatory for new or changed runtime behavior regardless of
optional-test wording in the core workflow. Group tasks by behavior: meaningful
Red, minimal Green, refactor and verification before the next behavior. Include
all applicable acceptance, error and recovery checks from the plan. Record final
validation tasks separately from fast development feedback. Avoid duplicate tests
and reports. If the TDD extension is installed, use its test list and cycle log
as the execution record rather than creating competing records.
